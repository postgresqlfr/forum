Erreur 1069: L'échec d'une ouverture de session a empêché de démarrage

Bonjour.

J'ai installé PostGreSql 8.2 sur un poste local sous Windows XP Pro (poste sur un réseau professionnel, pare-feu Windows désactivé), celui-ci a bien fonctionné quelques jours (avec des arrêts et redémarrage de CP), et depuis hier matin, le service PostGres ne tourne plus et je n'ai plus la possibilité de redémarrer.
L'utilisateur Postgres est administrateur et a tous les droits.
Les fichiers ".conf' contiennent apparemment les bons paramètres.

J'ai l'erreur suivante :
"Impossible de démarrer le service PostGreSQL Database 8.2 sur Ordinateur local.
Erreur 1069 : L'échec d'une ouverture de session a empêché de démarrage du service."

Si je tente de me connecter à la base via PgAdminIII, j'ai le message suivant :

"Une erreur s'est produite :
Error connecting to the server: n'a pas pi se connecter au serveur : Connection refused (0x0000274D/10061)
Le serveur est-il actif sur l'hôte <<127.0.0.1>> et accepte-t-il les connexions TCP/IP sur le port 5432 ?"

A noter que ce n'est pas la première installation et utilisation de PostGreSql8.2 que j'effectue, mais je n'avais encore jamais rencontré ce problème.

Merci, si vous avez de pistes à m'indiquer (pb anti-virus, etc).

Cordialement.

Christophe.

Re : Erreur 1069: L'échec d'une ouverture de session a empêché de démarrage

Bonjour,

si le mot de passe de l'utilisateur postgres a changé, il faut le paramétrer sur le service correspondant. L'utilisateur postgres doit également disposer du privilège "ouvrir une session en tant que service". Le fait de resaisir le mot de passe sur le service postgres donnera ce droit si celui-ci a disparu.
