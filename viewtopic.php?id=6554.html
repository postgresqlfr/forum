Choix SGBDR

Bonjour à tous,
Ceci est mon premier message sur ce forum.
Voici l'objet de ma question : Depuis une dizaine d'années maintenant, je diffuse des stats d'avant match sur les matchs de rugby. Ce travail est exclusivement réalisé avec Excel.
Aujourd'hui, je souhaite tout réécrire sur python mais je me questionne encore sur le choix de la SGBDR. On m'a fortement déconseillé Mysql et du coup j'hésite entre Postgresql et sqlite.
Je pense que certaines tables pourraient atteindre 20000 enregistrements environs.
Que me diriez vous pour me convaincre de choisir postgresql ?
Un grand merci par avance de vos réponse.
Je vous souhaite une excellente journée

Re : Choix SGBDR

Bonjour,

De nos jours gérer 20000 enregistrements ne représente vraiment aucun soucis quelquesoit le moteur de base de données.  Vous devriez plutôt choisir un moteur selon les fonctionnalités dont vous avez besoin.  Si votre utilisation se limlite à des types classiques (entier, chaine de texte etc), et du SQL vraiment classique, n'importe quel moteur fera l'affaire.  Dans votre cas si vous n'avez pas spécialement de compétences sur postgres je vous conseillerais plutôt de partie sur sqlite.  La maintenance / sauvegarde est bien plus facile et vous pouvez stocker la base avec votre code.

Julien.
https://rjuju.github.io/
