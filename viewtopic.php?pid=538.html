Re : fichier dans répertoire pg_xlog

Le coup des checkpoint très fréquent est normal lors de la restauration d'une grosse base de données si vous n'avez pas augmenté la valeur des variables checkpoint_segments et checkpoint_timeout.

Quelle version de PostgreSQL ? avez-vous activé l'archivage des journaux de transactions ? pour infos, les fichiers WAL sont des journaux de transactions. Ils sont nécessaires à PostgreSQL. Ils sont normalement utilisés de façon cyclique par PostgreSQL lors des checkpoints.

Avoir des instructions COPY pour une restauration est normale, c'est le fonctionnement par défaut. Par contre, avoir des erreurs sur les COPY indique que la restauration ne se fait pas.

Ce qui est encore plus troublant, ce sont ces messages :

2009-01-11 13:21:06 CET FATAL:  n'a pas pu dupliquer la socket 1364 pour le serveur : code d'erreur 10022
2009-01-11 13:21:13 CET LOG:  could not signal for checkpoint: No such process

Pour pouvoir mieux vous aider, il faudrait nous indiquer le numéro de version de PostgreSQL et nous donner le fichier de configuration (postgresql.conf).

Guillaume.

Première chose, il faut arrêter la restauration. Et voir, un peu plus tard, si le nombre de journaux de transactions diminuent très fortement. Il faut aussi vérifier que tous les processus sont là. Sous Windows, ça va être compliqué. Il n'y a à ma connaissance qu'un seul moyen : scruter les traces.

Copier le répertoire base ne suffira pas. Il faut aussi avoir les autres répertoires qui se trouvent dans le même répertoire parent que base. De plus, il doit s'agir aussi d'un Windows. Enfin, si le premier ordi est en 64 bits, le second doit aussi l'être. Cela étant dit, cela ne résout pas votre vrai problème. Ça ne fait que le cacher.
