Re : Methode de SVG fiable

avant de generer le pg_dump_all puis je estimer la taille que cela prendre ?

Non, c'est très difficile. Les objets binaires prennent beaucoup de place, les index au contraire sont pratiquement invisibles tellement ils ne prennent pas de places. Sans compter que certaines données sont stockées compressées dans la base alors qu'elles ne le sont pas dans la sauvegarde.

je veux sauvegarder ma base via pg_dumpall est ce  la solution la plus serieuse meme si un jour je  restore ce dump  via une version de postgres supérieure

Que ce soit pg_dump ou pg_dumpall, vous pourrez les restaurer sur une version majeure supérieure.

est ce aussi bien de ne sauvegarder que le repertoire DATA et si un jour j'ai une version superieure de postgres et que je copie ce DATA cela marchera t'il ?

Vous pouvez ne sauvegarder que le répertoire data à condition que postgres soit arrêté. Vous pouvez le faire alors qu'il est démarré grâce à la méthode PITR dont parle kenrio mais cela demande des étapes supplémentaires qui ne rendent pas le processus simple. Par contre, cette sauvegarde ne fonctionne pas avec une version majeure supérieure.

Guillaume.
