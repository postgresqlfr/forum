Migration de SQL Server vers PostGreSQL

Bonjour à tous,

Je souhaite savoir est ce qu'il existe une (ou des) solution(s) pour pouvoir de migrer depuis SQL Server 2000 vers le SGBDR de PostGreSQL.

Sachant que j'ai un certain nombre de tables qui contiennent pas mal de lignes, des procédures stockées et des fonctions qui existent sous SQL Server, ainsi que des DTS (Data Transfert Service) qui sont chargés d'importer des données depuis un fichier texte formaté vers les tables de SQL Servers .

Quelle sont les modalités d'importations pour les différents objets (tables, procédures stockées, DTS) ?

Existe t'il sur PostGreSQL un équivalant au DTS de SQL Server qui permet d'importer des données vers le SGBDR à partir d'un fichier .

En vous remerciant d'avance.

Cordialement.

Re : Migration de SQL Server vers PostGreSQL

Pour le schéma, un export SQL est le plus simple. Pour les données, soit un export SQL soit un export CSV.

Par contre, pour les procédures stockées, ce sera à réécrire manuellement.

Concernant DTS, ça a l'air très puissant. Il n'existe pas d'équivalent sous PostgreSQL. Vous pouvez charger des fichiers CSV dans PostgreSQL, mais toute la partie transformation de données devra se faire après chargement des données.

Guillaume.

Bonjour,

Vous pourriez utiliser un logiciel ETL open source pour faire votre migration.

Talend Open Studio est un outil ETL open source pour des experts de l'intégration de données avec un GUI fonctionnel, aisé à apprendre pour un utilisateur non-technique. Ce qui distingue Talend lorsque des utilisateurs business l'utilisent, c'est son composant Tmap permettant à l'utilisateur d'avoir une vue graphique / fonctionnelle du processus d'intégration.
Pour plus d'information: http://www.talend.com/
